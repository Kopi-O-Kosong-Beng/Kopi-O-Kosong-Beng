# Kopi Order Profile Design

Date: 2026-07-26

Supersedes `2026-07-19-github-profile-signal-lab-design.md` and
`2026-07-19-profile-easter-egg-clarity-design.md`.

## Why the previous design is being replaced

The signal lab profile failed on four counts, all confirmed by ZF:

1. **Too empty.** A banner, one sentence, and three links read as an unfinished
   placeholder rather than a deliberate minimalism.
2. **Too cold.** The engineering blueprint palette and schematic language had no
   warmth or humour in it. It read as a lab instrument, not a person.
3. **Hid too much.** Mystery only works when there is something to find. The
   profile withheld everything, so the mystery was the entire content.
4. **The artwork missed.** The schematic direction was the wrong vibe, and its
   central motif was wrong on the facts: it drew rising steam above a drink whose
   name (`beng`) means iced.

## Purpose

The profile has one job: make a visitor like Zhi Feng within ten seconds and want
to click through to the portfolio.

It is the trailer, not the film. The portfolio at
`https://zhifeng-portfolio.vercel.app/` is the film, and it already holds the
case studies, the architecture, and the numbers. The profile must not compete
with it.

## Positioning

### pitchMe leads

Zhi Feng is introduced as co-founder and CTO of pitchMe, described plainly and
warmly. This is both honest and load bearing: a profile that reads as a proud
founder repping their company cannot be read by the pitchMe team as a founder
looking for the exit.

### No job seeking signal anywhere

The README never states or implies that Zhi Feng is a student looking for work.
Banned outright: availability windows, internship dates, "open to
opportunities", "seeking", "available for hire", "let's connect about roles".

Recruiters get everything they need from the portfolio link plus the evident
quality of the profile itself. That is the whole mechanism.

### No metrics on the surface

Zero hard numbers appear in either README. Specifically excluded: S$71K,
237 youth, 87.5% agreement, 34% to 16% hallucination rate, 51% setup time,
CGPA, award placements, funding, team counts.

Competence is conveyed through the specificity of the descriptions instead. "A
two player math game with no CPU in it" lands harder with an engineer than "117
state FSM" does with anybody, and it is funnier.

No figure may appear in either README.

Revised 2026-07-26 after ZF review: an earlier version permitted `18 m`, a diving
certification depth. ZF's objection was that nobody reads `18 m` as scuba without
already knowing the convention, so the joke could not land. The line now says
scuba diving in plain words and carries no number at all.

### The craft is the evidence

The strongest signal of ability is silent: a hand built, theme aware, animated
SVG generated by a committed Python script, guarded by tests. Anyone curious
enough to open the repo finds it. Nobody is told about it.

## Writing voice

These rules bind all copy in both languages. They exist because ZF explicitly
asked that the writing not sound like AI.

### Hard rules

1. **No dashes as punctuation.** No em dashes, no en dashes, no hyphen used as a
   connector or an aside. Hyphens survive only inside words that are genuinely
   spelled that way, such as `co-founder`. This is the single loudest AI tell and
   removing it forces plainer sentences.
2. **No rule of three.** Do not build lists or clauses in balanced triplets.
3. **No antithesis constructions.** Ban "not just X, but Y", "it is not about X,
   it is about Y", and every variant.
4. **No summarising closer.** Paragraphs stop when the thought stops. They do not
   restate themselves at the end.
5. **Uneven rhythm.** Sentence lengths must vary noticeably. Fragments are
   allowed and encouraged. Every bullet in a list must not share the same shape.
6. **Banned vocabulary.** passionate, leverage, seamless, robust, cutting edge,
   journey, showcase, delve, dive into, tapestry, realm, landscape, testament,
   elevate, unlock, empower, foster, dedicated, driven, enthusiast.
7. **Real opinions over neutral description.** "That is where the interesting
   bugs live" earns its place because it is a claim a person would actually make.

### Accuracy rules

Copy is bound by the confirmed facts in the vault at
`d:\SUTD\Internship_finding\AGENTS.md` and `Experience/`. Nothing gets inflated
for the sake of a better line.

One correction already applied: the vault records taekwondo as "CCA Gold with
Honour", which is a co-curricular grade and not a competition medal. The copy
therefore says he competed and was bad at first. It does not claim a gold.

## Bilingual structure

Two files, each a complete profile:

- `README.md` in English, which is what the GitHub profile page renders.
- `README.zh.md` in Simplified Chinese.

Each carries a language line directly beneath the signboard, reading
`English · 中文`, where the current language is plain text and the other is a
link. The Chinese file links back with a relative path; the English file links
forward the same way.

Known limitation, accepted: a GitHub profile page always renders `README.md`, so
the Chinese version opens in the repository file view rather than as a profile
page. This is the standard bilingual repository pattern and it renders cleanly.

The Chinese version is written as Chinese, not translated from the English. It
carries the same content and the same humour, phrased the way ZF would phrase it
in Mandarin. AGENTS.md records Mandarin as bilingual level, so the register
should be natural and unmarked, not textbook and not internet slang.

The signboard artwork is shared between both languages. Its wordmark is
romanised Hokkien and Malay already, and it carries `谢梓峰`, so no Chinese
variant of the art is needed.

## README composition

Both language files follow the same eight part order:

1. The theme aware animated kopi signboard, via `<picture>`.
2. The language switch line.
3. A short first person introduction. Three sentences at most.
4. `NOW SERVING` / `今日供应`: pitchMe, with his role, in plain sentences.
5. `ON THE SIDE` / `配菜`: four other things he has built, described
   evocatively, with no project links and no metrics.
6. `ALSO IN THE CUP` / `杯里还有`: four things he does that are not work.
   Taekwondo, diving, marathons and mountains, table tennis.
7. A links line, framed as the full menu, pointing to the portfolio first, then
   pitchMe, LinkedIn, and email.
8. Two collapsed `<details>` blocks, then a closing signature line.

### The two details blocks

Both hold personality only. Neither holds anything a visitor needs in order to
understand the profile, and neither holds metrics.

- **why kopi o kosong beng?** Explains the order. Kopi is coffee, o means no
  milk, kosong means no sugar, beng means iced. Closes by pointing out that the
  ice in the signboard glass is deliberate.
- **what's brewing** A short current state note. Three facts: still at SUTD,
  flying to Waterloo at the end of August for an exchange semester, and one
  specific thing he is currently building. The default for the third is the
  portfolio site he is putting together, which is true as of this date and is
  already public knowledge via the portfolio link. ZF may swap it for something
  else at review. This block is the element that makes the profile feel alive and
  currently maintained, and it is the one part expected to be edited over time.

### Closing line

`no sugar. never was.` in English, `不要糖。从来都不要。` in Chinese.

### Excluded from the README

No shields.io badges. No skillicons wall. No readme typing SVG. No GitHub stats,
streak, trophy, or language cards. No contribution snake or 3D graph. No mermaid
architecture diagram. No project table. No skills list. No scheduled workflows
or third party profile services.

## The signboard artwork

### Files

- `assets/kopi-sign-light.svg`
- `assets/kopi-sign-dark.svg`

Selected by a `<picture>` element with `prefers-color-scheme` sources, with the
light variant as the `<img>` fallback. Both variants share identical geometry and
identical animation timing. Only colour tokens differ.

Both are produced by `scripts/generate_kopi_sign.py`, which holds the geometry
once so the two variants cannot drift apart.

### Content

A hawker stall signboard. Inside the panel:

- the wordmark `KOPI O KOSONG BENG`
- beneath it, smaller, `chia zhi feng · 谢梓峰`
- a small `singapore` mark
- to one side, a tall glass of iced kopi: dark coffee, ice cubes, a straw, and
  condensation beading on the outside
- along the bottom, a specials strip headed `TODAY'S BREW` listing the stack in
  monospace: `python · c++ · typescript · ros · fpga · gcp`

The specials strip was added 2026-07-26 after ZF review. The first version of the
signboard carried no engineering signal at all, which lost half the brief: the
profile read as someone who likes coffee and sport, with the competence buried in
prose nobody scans. A hawker stall lists what it serves, so this one lists code.
It stays typographic and part of the sign, which is what keeps it from becoming
the badge wall the rest of this spec exists to prevent. It names tools, not
achievements, so it does not compete with the portfolio.

The drink is iced because `beng` means iced. This is the correction of the
previous design's central error and it should not be undone.

### Palette

Light variant: cream paper ground, kopi brown lettering and linework, one amber
accent, pale blue white for ice highlights.

Dark variant: warm espresso near black ground, cream lettering, the same amber
accent, ice highlights held bright enough to read.

Both variants keep the wordmark and the name at practical contrast against their
ground. No blueprint cyan appears in either.

### Type

No web fonts. GitHub proxies README images and will not load remote font files,
so all text uses generic family stacks. The hand lettered character comes from
letter spacing, weight contrast, and slightly irregular baselines rather than
from a typeface.

### Motion

Two or three condensation droplets sliding down the glass on a slow loop.
Nothing else moves. No flashing, no fast cycles.

Each SVG contains a `prefers-reduced-motion: reduce` rule that halts all motion
while leaving the artwork complete. The first frame must read as a finished sign
in case GitHub's proxy does not play the animation.

### Responsive behaviour

`viewBox="0 0 900 280"`, scaling to README width. The wordmark, the name, and the
glass all sit inside a mobile safe central area. Nothing overlaps and nothing
clips at narrow widths. Secondary marks may drop in contrast at small sizes but
must remain legible.

### Accessibility

Concise alt text describing the signboard. No information carried by colour or
motion alone. Both READMEs remain fully understandable with images disabled.

## Tests

`tests/test_profile.py` is rewritten to lock this design in. The vault contains an
older profile draft at
`d:\SUTD\Internship_finding\Portfolio\github-profile-README.md` that uses a
typing SVG banner, shields, a skillicons wall, a mermaid diagram, and a full
metrics dump. These tests exist so that draft cannot creep back in.

Assertions, applied to both README files unless noted:

1. Both SVG files parse as valid XML.
2. Both READMEs contain a `<picture>` element with a dark source, a light source,
   and an `<img>` fallback.
3. Neither README contains `shields.io`, `skillicons`, `readme-typing-svg`,
   `github-readme-stats`, `streak-stats`, `github-profile-trophy`, or
   `contribution` graph or snake references.
4. Neither README contains a job seeking phrase. Case insensitive check against:
   `seeking`, `open to opportunit`, `available for`, `looking for a role`,
   `internship`, `hire me`.
5. Neither README contains an excluded metric string: `S$71K`, `71K`, `237`,
   `87.5`, `34%`, `16%`, `51%`, `4.57`, `18,000`.
6. Neither README contains an em dash or an en dash character.
7. Neither README contains any entry from the banned vocabulary list. Single
   words match on word boundaries and multi word entries match as exact phrases,
   so the hobby word `diving` does not trip the banned phrase `dive into`.
8. Both READMEs link to the portfolio, pitchMe, LinkedIn, and the email address.
9. Both READMEs contain exactly two `<details>` blocks.
10. `README.md` links to `README.zh.md` and `README.zh.md` links back to
    `README.md`.
11. `README.md` closes with the English signature line and `README.zh.md` closes
    with the Chinese one.

Test 5 checks bare number strings, so it also guards against a metric arriving in
a reworded sentence. `18 m` is permitted because it is a certification depth used
as a joke, and it is not on the excluded list.

## Verification

Implementation is complete only when all of the following hold:

1. `tests/test_profile.py` passes in full.
2. Both SVG variants render without clipping at desktop and narrow widths, in
   both GitHub themes.
3. Reduced motion yields a complete static signboard.
4. Every link in both READMEs resolves to its intended destination.
5. The language switch works in both directions on GitHub.
6. Markdown and HTML nesting are valid for GitHub's renderer.
7. `git diff --check` reports no whitespace errors.
8. The final diff touches only the files named in this spec.
9. A cold read of both READMEs finds no sentence that sounds machine written.
